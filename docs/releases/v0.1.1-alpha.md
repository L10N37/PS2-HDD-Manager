# PS2 HDD Manager v0.1.1-alpha

This is the second public alpha and the new reliability baseline.

`v0.1.0-alpha` was primarily a proof-of-concept / early hardware-validation release. It proved the core formatter, APA/PFS workflow and Extended APA approach on real hardware, but the desktop manager still had alpha-quality issues around heavily populated APA chains, long transfer queues, refresh/re-entry and large-library performance.

## Large-library hardware stress

A populated 2 TB drive was stress-tested with a 602-title queue:

- 602 / 602 processed successfully
- 601 newly installed
- 1 exact existing game detected and safely skipped
- heavily populated APA chains beyond the original 256-header ceiling
- no right-pane use-after-free crash during the completed run
- no blind duplicate-writing retry

On the test setup, the 601-game write took roughly 16 hours at approximately 40-60 MiB/s.

That duration is **not considered final performance**. The current safety-first build repeatedly checks destination state between games. Those scans become increasingly expensive as the disk fills.

## Current improvements

## Extended APA

The earlier 4 TB hardware validation remains an important proof point:

- FHDB boot from Bank 0
- Bank 0 and Bank 1 game installation
- Bank 0 and Bank 1 game launch on real hardware
- Bank 0 artwork shared with upper-bank games
- automatic installation of the matching Extended APA OPL build

Renewed 4 TB / AUTO rollover stress testing is still planned after the next transfer-planning rewrite.

## Known alpha limitation

Large queues are currently much slower than they should be because manager-side destination scans, duplicate checks and AUTO-space calculations happen too often.

The next branch will move that work into a **single pre-transfer inventory/planning pass**.

## Next development targets

### One-time transfer preflight / AUTO bank planning

Before the first write:

1. scan all selected source images once
2. identify game IDs/media/sizes once
3. optionally scan the destination HDD for duplicates once
4. build an in-memory existing-game map
5. read each bank's APA/free-space map once
6. calculate all 128 MiB allocation requirements once
7. assign the entire queue to Bank 0 / Bank 1+ before transfer
8. show the complete plan for review
9. write the queue without redundant manager-side full-bank rescans
10. perform final verification

Duplicate scanning will be optional, with conservative identity + media + size verification when enabled.

### PS2 Batch Renamer / audited database integration

Reuse the core logic and audited title database from:

`L10N37/PS2-ISO-Batch-Renamer-`  
reference release: `v4.0.1`

Planned manager workflow:

- identify ISO/CHD games by startup/game ID
- detect duplicate IDs in the selected source set
- audited title lookup
- preview proper filenames
- optional automatic rename before transfer
- optional game ID in filenames
- renaming remains optional: identification/duplicate checking/bank planning must work without changing source files

### Automatic PS1 POPS / POPStarter setup

Planned setup should make PS1 HDD use largely automatic:

- reserve/configure an appropriate Bank 0 POPS storage area during HDD setup
- user-selectable POPS reserve size
- create/manage `__common/POPS` and required `__.POPS*` storage
- validate/copy user-supplied proprietary POPS runtime files (never redistribute Sony runtime files)
- install redistributable launcher/homebrew components where licensing allows
- identify PS1 disc IDs
- prepare/install VCD titles
- support multi-disc titles as separate discs
- detect/skip existing exact matches
- initially keep POPS storage in Bank 0 until any Extended APA path is specifically validated

### Artwork follow-up

Make ART handling destination-aware before downloading/copying:

- inventory existing OPL ART once
- skip already-present exact artwork where possible
- avoid unnecessary re-downloads/re-writes
- retain real download and PFS-write progress

## Status

Linux/Fedora is the hardware-tested platform.

Windows physical-disk workflows remain experimental.

This release is **alpha / pre-release software** and performs raw physical-disk writes. Verify the target device before any destructive operation.
